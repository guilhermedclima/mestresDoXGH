💥 Quebrar de propósito

Os quatro jeitos
de quebrar

pip install funciona em cinco segundos.
O que toma tempo na vida real são estes quatro.

💥 nº 1

A biblioteca que não existe

import tabelinha_magica

ModuleNotFoundError: No module named 'tabelinha_magica'

Quer dizer uma de três coisas, nesta ordem de probabilidade:

  • você não instalou
  • escreveu o nome errado
  • instalou no lugar errado
💥 nº 2 · o que mais confunde

Nome de instalação ≠ nome de import

Você instalaVocê importa
pip install scikit-learnimport sklearn
pip install pillowimport PIL
pip install beautifulsoup4import bs4
pip install opencv-pythonimport cv2
pip install pyyamlimport yaml

Não tem regra.
Não dá para deduzir.

São nomes históricos, escolhidos por pessoas diferentes em épocas diferentes.

E é por isso que você lê a documentação.

A primeira linha de qualquer página mostra o pip install e o import.
Decorar é impossível. Consultar leva cinco segundos.

💥 nº 3 · o mais frustrante

"Eu instalei e ele diz que não existe"

Você instala, dá certo, roda o programa — e ele jura que a biblioteca não existe.

A causa: o pip instalou num Python e o programa rodou em outro.

Como conferir

Compare os dois caminhos

No código

import sys
print(sys.executable)

No terminal

pip -V

Não bateram? Achou o problema.

VS Code: Ctrl+Shift+P → Python: Select Interpreter.
No Colab isso não acontece — só existe um Python lá.

🔑 Guardem esta

A receita que resolve 90% dos casos

python -m pip install nome-da-biblioteca

Garante que o pip é o do mesmo Python que vai rodar seu código.

Pegue o hábito e você não vê mais esse erro.

💥 nº 4 · esse é de segurança

E se eu digitar pandsa?

Às vezes: erro de não encontrado.

Às vezes: instala.

Existe gente que registra pacote com nome quase igual ao de bibliotecas famosas, esperando o erro de digitação. Chama typosquatting.

Regra prática

pip install roda com as suas permissões

  • Use o link da documentação oficial ou do PyPI — não o primeiro resultado de busca
  • Olhe downloads e data da última versão na página
  • Desconfie de pacote novo, com poucos downloads e nome parecido com um famoso

Não é paranoia. Já aconteceu com biblioteca grande.

O problema

"Na minha máquina funciona"

Você termina o Projeto 2, manda para um colega, e ele abre:

ModuleNotFoundError

Óbvio — as bibliotecas estão na sua máquina.

Como você diz a ele o que instalar?

A solução é um arquivo de texto

requirements.txt

Você gera

pip freeze > requirements.txt
openpyxl==3.1.5
pandas==3.0.2
qrcode==8.2
rich==15.0.0

Ele instala

pip install -r requirements.txt

Um comando, e ele fica com exatamente as mesmas bibliotecas que você.

Por que a versão está ali

Biblioteca muda

print(pd.__version__)   # 3.0.2

O que funcionava na versão 1 pode ter mudado de nome na versão 3.

Travar a versão é dizer: funciona com esta aqui.

⚠️ E quando não tem?

Nem toda biblioteca expõe a versão

import qrcode
print(qrcode.__version__)

AttributeError: module 'qrcode' has no
attribute '__version__'

Mas o Python sabe — porque o pip anotou.

🔑 Funciona para qualquer pacote

O jeito que nunca falha

from importlib.metadata import version

print(version("qrcode"))   # 8.2

Tendo __version__ ou não.

Só para vocês saberem que existe

Ambiente virtual

Dá a cada projeto a sua própria caixa de bibliotecas, sem misturar.

É a solução definitiva para o erro nº 3.

O nome é venv. Vai aparecer no Projeto 2 — hoje basta saber que existe.
