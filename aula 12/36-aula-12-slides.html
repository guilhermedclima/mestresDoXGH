A pergunta literal que ficou

Quem está do outro lado?

A exceção boazinha

Instala e importa com o mesmo nome

pip install requests
import requests

resposta = requests.get("https://api.agify.io?name=guilherme")
print(resposta)
<Response [200]>

Três linhas. Essa é a aula inteira — o resto é cuidado.

O que aconteceu na rede

Quatro passos

  • o Python abriu uma conexão com api.agify.io
  • mandou um pedido: "me dá o que está em /?name=guilherme"
  • o servidor respondeu com um status e um corpo de texto
  • o requests embrulhou as duas coisas num objeto

Esse objeto não é o dado. É o envelope.

Dentro dele tem o status e tem o corpo. A gente vai abrir os dois.

O corpo cru

Chaves, dois-pontos, vírgula

print(resposta.text)
{"count":5405,"name":"guilherme","age":34}

Isso é JSON — a Aula 7. Vocês já sabem ler isso.

A API olhou 5405 Guilhermes e apostou 34 anos. Errou. Mas repare no count: ela disse em quantos dados se baseou.

O que o servidor achou do seu pedido

Parâmetros

Aquele ? no meio da URL

https://api.agify.io?name=guilherme
                    ↑     ↑      ↑
                    │     │      └── o valor
                    │     └── a chave
                    └── começa a lista de parâmetros

Depois do ? vem chave=valor, e & para juntar mais de um.

É assim que uma URL atende mil pedidos diferentes.

Dois jeitos de montar

Deixe o requests montar

Colando na mão

requests.get(
  "https://api.agify.io?name=" + nome)

No dia em que o valor tiver espaço, acento ou &, a URL sai quebrada.

Com params=

requests.get(
  "https://api.agify.io",
  params={"name": "maria",
          "country_id": "BR"})

O requests sabe escapar. Você não precisa saber.

https://api.agify.io/?name=maria&country_id=BR
{'count': 3622, 'name': 'maria', 'age': 59, 'country_id': 'BR'}

Mesma API, mesmo endereço, parâmetro diferente, resposta diferente. Ler a documentação de uma API é, quase sempre, descobrir que parâmetros ela aceita.

O ViaCEP põe o parâmetro no caminho

Buscador de CEP que não quebra

  • CEP certo → rua, bairro, cidade, UF
  • CEP que não existe → "CEP não encontrado"
  • Malformado, servidor fora, internet caída → avisa sem stack trace na cara do usuário
11013001   →  deve achar (Santos)
99999999   →  não existe
123        →  malformado

Enquanto não passar nos três, não está pronto.

Solução de referência

Devolve o dado e o problema

def buscar_cep(cep):
    cep = cep.strip().replace("-", "")
    url = f"https://viacep.com.br/ws/{cep}/json/"
    try:
        r = requests.get(url, timeout=5)
    except requests.exceptions.RequestException as e:
        return None, f"não deu para falar com o servidor ({type(e).__name__})"
    if r.status_code != 200:
        return None, f"o servidor recusou (status {r.status_code})"
    try:
        dados = r.json()
    except requests.exceptions.JSONDecodeError:
        return None, "o servidor não mandou JSON"
    if "erro" in dados:
        return None, "CEP não encontrado"
    return dados, None

Devolve dois valores e não dá print de nada. Função busca; quem chamou decide.
