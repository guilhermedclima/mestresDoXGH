Primeiro passo

Notebook não é programa

Notebook é bancada: você roda célula fora de ordem, deixa variável solta, conversa com o código.

Programa é outra coisa: um arquivo, de cima para baixo, do começo ao fim.

Agendador não sabe apertar play em célula.

O arquivo

Um .py, rodado pelo terminal

> python organizador.py
12 arquivos movidos

Sem Jupyter, sem navegador, sem play. Só o Python e o arquivo.

É assim que todo programa de verdade roda — e é assim que o agendador vai chamar.

Para não travar a pasta no código

Receber argumento: sys.argv

import sys

pasta = sys.argv[1] if len(sys.argv) > 1 else "."
> python organizador.py "C:\Users\guilherme\Downloads"

Mesmo script, pasta diferente. Sem editar uma linha.

O porteiro

if __name__ == "__main__"

def organizar(pasta):
    ...

if __name__ == "__main__":
    organizar(sys.argv[1])

Traduzindo: "só execute isto se EU for o programa principal".

Sem ele, importar seu arquivo em outro lugar dispara tudo sem querer.

E agendamento VAI rodar duas vezes

Duas vezes é o normal, não a exceção

  • Você testa na mão
  • O agendador roda no horário
  • A máquina hiberna e ele roda ao acordar
  • Você clica em "Executar" só para conferir
A palavra e as duas saídas

IDEMPOTENTE

Rodar uma vez ou dez vezes dá o mesmo resultado.

  • Verificar antes de agir — "já existe? já foi feito? então não faço"
  • Marcar o que já foi feito — uma lista, uma coluna de data, um nome de arquivo
🛗

O botão do elevador

Apertar dez vezes é igual a apertar uma. Idempotente.

Interruptor de luz não é:
apertar duas vezes desliga.

Diretório
de trabalho

Todo programa tem uma pasta onde ele "está".

No terminal é a pasta em que vocês estavam.
No agendador não é — e a escolha não é óbvia.

Mostrar, não contar

Dois caminhos diferentes

print("diretorio de trabalho :", os.getcwd())
print("onde o script mora    :", Path(__file__).parent)

Rodando de outra pasta, os dois divergem — e o arquivo relativo some.

Erro de arquivo sem caminho na frente? Desconfie de caminho relativo.

A solução é uma linha

Ancorar no próprio arquivo

AQUI = Path(__file__).parent          # onde o SCRIPT mora
ARQUIVO = AQUI / "relatorio.csv"      # não depende de onde chamou
  • arquivo do próprio projeto → Path(__file__).parent / "..."
  • caminho que o usuário passou → .expanduser().resolve()
  • caminho relativo em script agendado → nunca
Duas notas que valem o minuto

__file__ não existe em notebook

No Colab e no Jupyter você ganha um NameError.

É mais uma coisa que separa bancada de produto.

E aqui a Aula 9 muda de status

try/except deixa de ser zelo

try:
    shutil.move(item, destino)
    logging.info(f"movido: {item.name}")
except Exception as e:
    logging.error(f"falhou em {item.name}: {type(e).__name__}")

Sem except, o programa para no primeiro arquivo problemático — e os outros onze não são tratados.

É a diferença entre "falhou" e "falhou um de doze".
